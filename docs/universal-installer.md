# Universal and version-specific installers

Release titles use **Enhanced 0.4.1.0**, **Enhanced 0.3.0.0**, etc. Tags use
`v0.4.1.0`, `v0.3.0.0`, `v0.2.0.0` and `v0.1.0.0`. The final number starts at
zero and increments for Enhanced updates on the same Yapfast base. SDK/API
package versions are independent.

## Which installer to download

- `Yapfast-Enhanced-Universal-Installer.exe`: a small **online** dispatcher.
  Use its dedicated folder picker to choose the existing Yapfast folder (by
  default, `%LOCALAPPDATA%\Programs\Yapfast`). Missing `yapfast.exe` is reported
  on that page so you can correct the selection. It finds a stable Enhanced release for
  that exact executable, downloads and verifies its version-specific installer,
  then opens it for you to review and install. It does not bundle four apps.
- `Yapfast-Enhanced-Installer.exe`: the **offline** installer attached to a
  particular release. It supports only that release's exact official Yapfast
  fingerprint, or an already-managed Enhanced installation of that base.

Both paths keep the existing account/plugin data and delegate backups, scoped
shutdown, repair and restoration to the same version-specific manager. Save work
and finish calls/uploads first. The online wrapper does not create another
installed application or uninstall entry. Installing support on one version
never silently upgrades or downgrades Yapfast.

For an unsupported binary, the universal installer leaves it unchanged and
shows the latest supported Yapfast base listed on GitHub with its release link.
There is no automatic downgrade or plain-Yapfast download. A damaged Enhanced
state needs repair; unknown/repacked official binaries are not assumed compatible.

## Detection, integrity and cleanup

The dispatcher hashes the executable. For an intact managed Enhanced install,
it uses the original hash recorded by the existing manager. It scans at most ten
100-release GitHub pages, compares canonical four-part `v` tags numerically,
and ignores drafts, prereleases, source-only and foreign release URLs.

Each supported release must attach:

1. `Yapfast-Enhanced-Installer.exe`.
2. `yapfast-enhanced-for-<official-SHA256>.zip` (the exact compatibility marker
   and offline repair payload, generated by the normal packager).
3. `SHA256SUMS.txt`.

The GitHub asset API must supply a valid `sha256:` digest and size for the
installer. The dispatcher refuses missing digests, wrong URLs, oversized or
truncated files, and checksum mismatches. Downloads use HTTPS, bounded requests
and owned temporary folders that are removed on success, error or cancellation
of the matching installer. It checks that Yapfast did not change during download.
No credentials, account files or plugin data are opened. Network access contacts
GitHub; the installed binary hash is matched locally against its release catalog.

These packages are unsigned. SHA-256 checks detect changed bytes against GitHub's
metadata; they are not independent code signatures and do not protect against a
compromised repository/account. Do not publish an installer without matching source.

## Publishing and local builds

Push the reviewed source and create each matching tag before publishing assets.
Publish **Enhanced 0.4.1.0** as Latest. Do not mark older compatibility releases
as Latest. README links are prepared for those exact tags and will begin working
when the releases are published. The universal installer can be attached to the
main release; each compatibility release keeps its own offline installer.

Build the native app and manager, then run the version-specific packager as
shown in [release instructions](releasing-enhanced.md). After that, package the
universal installer with the same manager:

```powershell
python scripts/package-enhanced-universal.py --manager "<built-manager.exe>" --output .release/v0.4.1.0
```

This adds the universal installer to the shared checksum file. It does not push,
tag or publish anything. Unit tests cover catalog selection, initial zero
revisions, malformed tags/URLs, unsupported fingerprints, sizes and hashes.
The actual online download/handoff must be checked after the matching GitHub
releases exist; local tests cannot prove unpublished downloads work.

On Windows with Inno Setup 6 installed, verify the compiled folder picker with:

```powershell
python testing/test_enhanced_universal_folder.py --manager "<built-manager.exe>"
```

This runs a temporary, instrumented copy against valid and missing-executable
folders, including a custom path with spaces and Unicode. It exits before
version detection, downloads or installation and does not touch a live app.
